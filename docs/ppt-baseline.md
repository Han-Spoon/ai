## 7쪽 — Multi-Agent Orchestration

**일관된 분석과 유연한 확장을 실현하는 Hub&Spoke architecture**

### 핵심 설계 원칙

**1. Hub & Spoke Orchestration**

**Supervisor 중심의 통제형 Orchestration**

모든 Agent·Tool 호출은 Supervisor를 경유
직접 통신 없이 분기·재시도·결과 통합·실행 로그를 중앙 관리
→ 전체 판정 흐름과 책임 지점을 한 곳에서 추적

**2. Agent와 Tool의 Boundary**

**Agent는 판단하고 Tool은 수행한다**

Agent  LLM 기반 추론이 필요한 판단 노드 → 맥락 해석 · 검색 전략 · 신호 종합 등
Tool  정해진 절차를 수행하는 실행 노드 → OCR · DB 조회/저장 · 규칙/확률 계산 등

**3. Evidence-Aware Decision**

**확정 근거와 추정 근거를 분리한다**

검증된 Hard Evidence와 웹·확률 기반 Soft Evidence를 구분
근거의 출처·신뢰도를 함께 전달하고 Bayesian 추론에 반영
근거가 부족하면 억지로 확정하지 않고 Caution / 확인 질문으로 전환

**4. Modular & Extensible**

**모듈 독립 검증과 유연한 확장 지원**

Agent와 Tool을 느슨하게 분리해 개별 검증·교체 가능
새로운 검색·추천·지식 모듈도 Supervisor 인터페이스만 연결해 확장
일부 외부 리소스 실패 시에도 핵심 판정 흐름은 유지

### INPUT / OUTPUT

- **INPUT** — 메뉴판 이미지 / GPS 좌표 / 사용자 식단 프로필
- **OUTPUT** — 위험도 판정 결과 / 위험도 판정 근거 / 위험 재료 / 확인 질문

### 외부 연결

- **DB** — 식당별 응답 레시피 prior 증거 로그
- **가게 직원** — 질문, 답변
- **API 외부** — GPS/지도
- **웹** — 외부 레시피

### Supervisor Agent

입력 상태와 근거 수준을 기준으로
Agent와 Tool의 호출 순서와 조건 분기를 제어,
결과·오류·근거를 회수하여 하나의 판정 흐름으로 통합

`Routing` `State` `Evidence`

### Agent / Tool 구성

**① OCR Tool**
메뉴판 이미지에서 메뉴명·가격·설명 텍스트를 구조화하여 추출
`메뉴판` `텍스트 추출` `영역 구조화`

**② Menu Normalization Agent**
OCR의 오탈자·표기 변형·다국어 메뉴명을
문맥과 후보 지식을 바탕으로 표준 메뉴명으로 해석
`문맥 추론` `표준명 매핑` `불확실성 보존`

**③ Exact Feedback Tool**
검증 및 저장되어 있는 메뉴인 재료 확정 근거(Hard Evidence)를
조회하여 존재 / 부재 / 미확인 상태를 반환
`확정 근거 조회` `3-State`

**④ DB / Ontology Tool**  (예) 김치→액젓→새우)
메뉴·레시피·재료 계층과 알레르기·식이 제약 지식을 조회하여
복합 재료를 원재료 수준까지 확장하고 위험 속성을 연결
`레시피 조회` `재료 계층 확장` `위험 속성 매핑`

**⑤ Bayesian Tool**
확정되지 않은 재료에 대해 사전확률(prior)과
수집된 근거를 결합하여 해당 재료가 존재할 가능성을 갱신
`확률 추정` `Posterior 갱신` `불확실성 정량화`

**⑥ Web Search Agent**  (검색 실패 → NO_INFORMATION)
내부 근거가 부족하거나 DB 미등록 메뉴일 때 검색 여부, 쿼리,
출처 신뢰도를 판단하여 외부 레시피와 재료 근거를 보완
`조건부 검색` `출처 평가` `근거 수집`

**⑦ DB Update Tool**
새롭게 확보된 근거를 출처·신뢰도·검증 상태와 함께 저장,
Hard Evidence와 Soft Evidence를 분리 관리
`Provenance` `신뢰도 분리` `근거 저장`

**⑧ Decision Policy / XAI Agent**
사용자 식단 제약과 확정·추정 근거를 정책에 따라 종합하여
Safe / Caution / Danger를 판정하고 위험 재료·판정 근거·확인 질문을 생성
`정책 기반 판정` `근거 설명` `확인 질문`

**⑨ Curation Tool**  (위험도 판정과 추천 로직은 분리)
판정 완료 후 안전 후보를 대상으로 검증된 큐레이션/RAG 인덱스를
검색 및 랭킹하여 메뉴·한식 문화 콘텐츠를 추천
`메뉴 랭킹` `RAG 검색` `문화 콘텐츠`

## 8쪽 — Multi-Agent Orchestration

**Supervisor 조건부 호출 흐름**

### 핵심 실행 기준

**1 가게 단위 상태 관리**

모든 호출에 store_id 유지하여
가게별 확정 재료와 사전 확률이
섞이지 않도록 관리

**2 재료 단위 선택 실행**

확인된 재료는 그대로 유지
미확인 재료만 확장 · 추정하며, 전부 확인되면 확률 계산 생략

**3 숨은 재료 · 변형 확장**

복합 재료를 재귀적으로 확장 후
메뉴명에서 변형 재료를 태깅함

**4 정보 부족→보수적 판정**

검색 실패 시 확률 계산 생략 후
NO_INFORMATION으로 처리
웹 서치 실패 시 '없음'으로 처리,
안전으로 단정하지 않고 정보 부족
또는 경고 상태로 전달

### 1 Supervisor

가게 식별(store_id 유지) · 메뉴별 분기 · 호출 및 결과 취합

**흐름**

- **입력** — 메뉴판 · 가게 정보 / 사용자 제한 태그
- **① OCR Tool — 메뉴명 인식**
- **메뉴명이 모호한가?**
  - 예 → **② Menu Normalization Agent — 메뉴명 정규화** (의미 추론으로 메뉴명 보정)
  - 아니오 → **2 ③ Exact Feedback Tool — 확정 재료 조회** (가게에서 제공 재료 정보 · 사용자 피드백 우선 반영)
- **미확정 재료가 있는가?**
  - 아니오 → **확정 재료로 바로 판정**
  - 예 → **3 ④ DB / Ontology Tool — DB 기반 재료 조회** (재료 · 레시피 · 온톨로지 확인)
- **DB에 존재하는가?**
  - 예 → **⑤ Bayesian Tool — 확률 계산** (미확인 재료 포함 가능성 추정)
  - 아니오 → **⑥ Web Search Agent — 웹 근거 탐색** (검색 전략 수립 · 근거 검토)
- **웹 근거가 있는가?**
  - 아니오 → **4 정보 부족 처리** (NO_INFORMATION)
  - 예 → **5 ⑦ DB Update Tool — 새 근거 저장** (결과를 관리자 페이지에 업로드 검토 후 DB 갱신)
    → **데이터 출처 · 상태 저장** → **⑤ Bayesian Tool — 확률 계산**
- **# Supervisor agent — 확정 재료로 바로 판정** (확정값과 미확인 재료의 확률값 통합)
- **6 ⑧ Decision / XAI Agent — 최종 판정 생성** (Danger · Caution · Safe / 고위험 재검증)
- **⑨ Curation Tool — 추천 메뉴 정렬** (위험도와 근거 기준으로 정렬)
- **사용자에게 결과 제공** (근거 · 위험 재료 · 확인 질문)

### 5 검토 후 DB 갱신

웹 검색 · 변형 후보 → 관리자 검토 · 승인 → **DB Update Tool — 데이터 출처 · 상태 저장**
사장님 확인 정보 → 최소 n회 이상 시 기록 · 이상 여부 검사 → **DB Update Tool — 데이터 출처 · 상태 저장**

### 6 최종판단 기준 Danger, Caution, Safe

- Hard Evidence 있음 (사장님 확인 n건↑) → DANGER/SAFE 확정, n개월마다 재확인
- Hard Evidence 없음 → DANGER/SAFE 판정 불가, CAUTION + 확률 수치까지 제공
  정보 부족·충돌 케이스만(5~10%) → 고가 모델 재검증

### 3 베이지안 스코어링으로 재료 확률 추정

**베이지안 추정식**
α = k + 1
β = (n − k) + 1
p = α / (α + β)

레시피 속, 특정 재료가 들어갈 확률은?
Binomial의 켤레사전분포인 Beta 분포를 사전분포로 적용
train : test = 8 : 2, 레시피 단위 20% hold-out (검증 n≈974)
돼지고기가 '있는데 없다'고 판단하는 false negative 비용이 더 큼

메뉴별 AUC와 Jaccard 유사도 비교 (x축: Jaccard 유사도(평균), y축: AUC-ROC)

메뉴별 AUC와 Jaccard 유사도 평균 비교에서 양의 상관관계
(R = 0.76) 확인

메뉴와 재료의 유사도가 높을수록
모델의 예측 성능이 향상되는 경향을 보임

## 10쪽 — Ready for Real World

**실제 운영 조건까지 설계한 신뢰 가능한 서비스 구조**

### RAI 핵심원칙 적용

중심: 모두를 위한, 더 공정하고 안전한 AI — **Responsible AI**

**01 공정성**
언어, 알레르기, 종교 등 조건이 달라도
동일한 시스템 알고리즘으로 분석됨

**02 책임성**
AI 결론을 강요하지 않고
근거 확인, 직접 선택,
재스캔 및 기록 재확인 경로 제공

**03 투명성**
위험도 판단 결과(안전, 주의, 위험)와 함께
판단 근거와 대체 메뉴 설명 제공

**04 안전성과 보안**
